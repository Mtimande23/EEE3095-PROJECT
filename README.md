# STM32 Tic-Tac-Toe serial game server

EEE3095S CS Project 2026. The STM32F051C8 (UCT STM board) is the referee: it holds
the only copy of the game, validates every request and replies with the
authoritative result. A thin Tkinter client on the PC draws the board from those
replies and forwards clicks. The full protocol and state machine are in
[docs/PROTOCOL.md](docs/PROTOCOL.md), and the diagrams are in
[docs/](docs/) (see [Diagrams](#diagrams)).

The repository folder is itself the STM32CubeIDE project (an Empty Project: no
CubeMX, no HAL).


```
.project, .cproject    STM32CubeIDE project files (source folders: Core, Startup)
STM32F051C8TX_FLASH.ld linker script; Startup/ holds the startup code
Core/Src, Core/Inc     the firmware:
    game.c/.h            the rules (pure C)
    protocol.c/.h        framing, checksum, commands, state machine (pure C)
    board.c/.h           direct register access: 48 MHz clock, GPIO, USART1, SysTick, LCD
    main.c               super-loop: UART -> protocol, button, LED
    syscalls.c, sysmem.c generated by CubeIDE
gui/client.py          Tkinter + pyserial client
gui/ai.py              AI opponent (Easy / Medium / Hard), runs on the PC
tests/                 pytest harness that drives the serial link (63 tests)
sim/                   optional PC simulator of the board (Linux/macOS/WSL only)
docs/                  PROTOCOL.md, FSM, sequence, GUI flowchart, circuit, board test logs
```

## What you need

- The UCT STM32F051C8 board and a USB cable. Its ST-Link shows up on the PC as a
  virtual COM port, *STMicroelectronics STLink Virtual COM Port (COMx)*. The number
  differs from PC to PC (COM4, COM12, ...); you do not need to know it, because the
  GUI and the tests find the board by its ST-Link USB ID. No USB-UART adapter is
  needed: the ST-Link's port is wired to USART1 (PA9/PA10) for the newer STM32s.
- STM32CubeIDE (tested with 2.x).
- Python 3.9 or newer. On Windows tick *Add Python to PATH* when installing.

Install the Python packages once, from this folder:

```
python -m pip install -r requirements.txt
```

## 1. Build and flash the firmware

1. In STM32CubeIDE: *File > Import > General > Existing Projects into Workspace*,
   select this repository's folder (the one holding `.project`), *Finish*.
   Do not tick *Copy projects into workspace*.
2. Build with the hammer icon. The console should end with `0 errors`.
3. Connect the board and press *Run* (or *Run > Run As > STM32 C/C++ Application*).
   The console should end with `Download verified successfully`.
4. Press the board's reset button. The LCD is cleared and the LED (PB0) is off:
   the server is idle and waiting.

To start from scratch instead (WHICH YOU MIGHT NOT NEED TO DO SO YOU CAN MIZE): create an *STM32CubeIDE Empty Project* for
**STM32F051C8T6**, delete its `main.c`, and add the four firmware `.c` files to its
`Src` folder and the three `.h` files to its `Inc` folder. Nothing else is needed: the
firmware uses no HAL, CubeMX or CMSIS headers.

Board connections (set at the top of `board.h`, taken from the UCT board schematic):

| Part | Pins | What it does |
|---|---|---|
| UART | USART1, PA9 TX / PA10 RX, 115200 8N1 (`GAME_UART 2` for USART2 on PA2/PA3) | Link to the PC |
| Button SW0 | PA0, active low, internal pull-up | Abandons any game, sends `EVT:RESET` |
| LED D0 | PB0, active high | Off: idle. On: X to move. 1 Hz blink: O to move. 5 Hz blink: game over |
| LCD | RS PC14, E PC15, D4 PB8, D5 PB9, D6 PA12, D7 PA15 (4-bit, RW to GND) | Cleared at start-up |

## 2. Run the GUI

```
python gui/client.py
```

The GUI finds the board and selects its port. If you plug the board in after
opening the window, press *Refresh*. You can also pick a port from the list, or
name one on the command line (`python gui/client.py COM12`). Then:

1. *Connect*. The status reads "Connected. Press New game to start."
2. Pick a theme (*Classic* or *Zoro vs King*) and *Light/Dark* at the top right.
3. Type the two player names.
4. Choose the *Opponent*: *Friend* (two people) or *AI* with a *Level* and
   *You play* X (moves first) or O.
5. *New game*, then click cells. Rejected moves show the server's reason, the
   winning line is highlighted, and the cells lock until the next *New game*.
6. *Disconnect* and close the window when done, so the port is free for the tests.

Details:

- **AI:** *Easy* plays a random cell, *Medium* wins or blocks if it can (else
  random), *Hard* plays perfectly and never loses. The AI runs on the PC and only
  suggests a move: the GUI sends it as `MOVE:<P>:<n>`, so the STM32 validates every
  AI move exactly like a human's.
- **Scoreboard:** counts wins and draws while the app is open. A resign is a win for
  the other player; a button reset or a disconnect is not counted. It resets with
  *Reset score*, and starts fresh when the names, opponent, level or side change.
- **Checksum:** when ticked, every request gets the optional `*HH` suffix (XOR of
  the characters), for example `MOVE:4*1F`. The board rejects a frame whose checksum
  does not match with `NACK:CHECKSUM`.
- **Protocol log:** under the board, always visible: every frame sent (`>`) and
  received (`<`).

NB: TAKE A LOOK AT THE LED PB0 WHEN PLAYING(workflow defined in Protocol.md)

## 3. Run the automated tests

Close the GUI first (only one program can open the port), then:

```
python -m pytest tests --port auto
python -m pytest tests --port auto -v          # one line per test
python -m pytest tests/test_ai.py --port auto  # just the AI tests
```

`--port auto` finds the board on any PC and prints the port it used. To name the
port yourself, use it instead of `auto` (for example `--port COM12`), or set it once
with the `GAME_PORT` environment variable. Expected: `63 passed`, in about 30 to 40
seconds.

- `test_server.py` (48): the brief's required cases (`TestRequired`), server
  authority (all 8 win lines, out-of-turn, out-of-state, no rejected request changes
  the state) and robustness (oversized, garbage, partial-frame timeout, split
  frames, CRLF, checksum). Each test starts from IDLE.
- `test_ai.py` (15): every AI move is sent to the server and must be accepted, for
  all three levels and both sides; Hard never loses (checked offline against every
  possible opponent, and on the server); Medium takes wins and blocks.

## 4. Optional: the PC simulator

`sim/` builds the same `game.c` and `protocol.c` for the PC and serves them on a
virtual serial port, so the GUI and tests can run without a board. It is not part
of the CubeIDE project and needs Linux, macOS or WSL (`cc` and `make`). 
NB: SO this is just a quick test on the GUI without actually getting it connected to the board.

```
python -m pytest tests                  # no --port: builds and starts the simulator itself
cd sim && make
./gamesim --link /tmp/ttyGAME           # prints PORT /tmp/ttyGAME
python ../gui/client.py /tmp/ttyGAME
```

In the simulator's terminal, type `b` + Enter to press the virtual button; LED
changes are printed there.

## Troubleshooting

| Problem | Fix |
|---|---|
| `could not open port` / `Access denied` | Another program has the port open (the GUI, or a CubeIDE serial console). Close it. |
| GUI: "The server did not answer" | Press the board's reset button; if that does not help, flash again. |
| `'pytest' is not recognized` | Use `python -m pytest ...`. |
| `No module named serial` | `python -m pip install -r requirements.txt` |
| `--port auto: no board found` | Check the USB cable and that the board appears under Device Manager > Ports (COM & LPT), then give that port, e.g. `--port COM12`. |
